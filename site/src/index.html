Your own app host, on one small server.

nook runs static sites, web apps, background services and cron jobs on a single Debian VPS. Push to GitHub and it's live over HTTPS, every pull request gets its own preview, and a dashboard that works on your phone shows what everything is doing.

What you get

Deploy from any repo

A GitHub Action, or one curl from any CI, uploads your build with a deploy token. Static files, a server, a service or a cron job, from the same folder layout.

Every app on its own

Each repo gets its own Linux user, folder, memory and CPU limits, firewall rules and sandbox, so one app can't read or starve another.

Previews for every PR

Each pull request gets its own address, and it's gone when the PR closes.

A dashboard for your phone

Sites and their health, logs, secrets, domains and certificates, users, memory and disk over time, and one-tap updates.

A store of ready-made apps →

Analytics, file storage, push notifications, a database, a private npm and container registry, CI runners. Signed, pinned by hash, each an ordinary app.

Backups that restore

Daily to any S3-compatible bucket, encrypted and incremental. Restore one app, or the whole server onto a new one.

How it works

Two static Go binaries and Caddy on a Debian box. Each repo deploys into its own app; every folder in the app's sites/ is a live site, named by its hostname. No containers, no database to run, no account anywhere.

Push, and it's live

The Deploy page makes a token and a ready workflow for the repo. Merges to main go live; pull requests get a preview and a comment with its link.

A site with a health path is checked after every deploy, and the job fails if it doesn't come up.

See what each app is doing

Open an app for its memory and disk over the week, where it's heading, and each site's state. Limits change without a restart.

The server section says in one sentence whether there's room to spare, and what to upgrade when there isn't.

Install apps from a store

Catalogs are signed, and every download is checked against the hash the catalog pins. Updates roll back by themselves if the new version doesn't come up.

Browse the apps

Services by name

An app's nook.json asks for postgres; you pick the provider; the app sees DATABASE_URL and runs the same anywhere. The firewall opens the provider's port to exactly the apps bound to it.

Backups you can move with

restic snapshots to R2, B2 or any S3 bucket: daily, before every update, and on demand. A running database is dumped by its own hook, or paused for the moment it's read.

Restore one app's data, or a whole server onto a fresh install.

Install

On a fresh Debian 13 VPS, as root. It prints a one-time link to make your login; then set the dashboard's address and grant domains to apps on its Domains page.

# installs Caddy, swap, both binaries, and the dashboard
curl -fsSL https://raw.githubusercontent.com/sparkstonepdx/nook/main/setup-server.sh | sh

Open ports 22, 80, 443 (tcp and udp) and 8443. Then read the rest in the docs.
